Is GitHub safe?

GitHub has tools for securing accounts and controlling access, but safe habits still matter.

What makes GitHub safe?

GitHub provides features such as authentication methods, repository visibility options, and access controls. These features help, but they cannot guarantee that every uploaded file, dependency, or collaborator is safe. You should still review what you publish, who has access, and whether your account is protected.

Ways to protect your work

  • Use a unique password and a password manager. Use two-factor authentication (2FA) or a supported passkey, and store recovery methods somewhere safe.
  • A public repo is visible to everyone. A private repo limits access to authorized people. Check the visibility before publishing or inviting collaborators.
  • Give other people only the level of access they need and remove access when it is no longer needed. Be thoughtful about granting write or administrative access.
  • Do not commit passwords, access tokens, API keys, or private keys. Use environment variables and appropriate secret-management tools. A .gitignore file helps exclude untracked files, but it does not remove files already tracked by Git.

Public vs. private repositories

Public repository

Anyone can view the code, and others may be able to copy or fork it. Good for projects you want to share openly.

Remember: Never publish passwords, tokens, or other private information.

Private repository

Only you and people with permission can view it through GitHub. Good for projects you do not want to share publicly.

Remember: People you grant access to can still copy files, so only invite people you trust.

What to do if you accidentally upload a secret

For example: your real API token appears in a commit.

You should first revoke or rotate the token so it can no longer be used. Then assess possible misuse and follow GitHub's documented process for handling sensitive repository history; this can involve coordinating with collaborators. Deleting the file in a later commit or making the repository private does not automatically invalidate the exposed token or erase previous copies.

Before your next push, make sure you:

  1. Review which files changed.
  2. Did not include real credentials.
  3. Check the repository visibility.
  4. Only give intended collaborators access.
